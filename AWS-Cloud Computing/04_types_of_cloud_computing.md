## 🏗️ Service Models (The "Pyramid")

| Model | Full Name | You Manage | Example |
|:---:|---|---|---|
| **IaaS** | Infrastructure as a Service | OS, runtime, apps (provider gives raw building blocks) | AWS EC2 |
| **PaaS** | Platform as a Service | Just your app deployment (no OS/hardware config) | AWS Elastic Beanstalk |
| **SaaS** | Software as a Service | Nothing — fully managed product | Gmail, Office 365, Salesforce |

```
IaaS (most control) → PaaS → SaaS (least management)
```

> 💡 Bonus: **Serverless (Functions as a Service)** — you manage only code and data; the provider handles everything else.

---

## 🌐 Deployment Models

| Model | Description | Common Users |
|---|---|---|
| ☁️ **Public Cloud** | Everything built on the provider's infrastructure ("cloud-native") | Startups, SaaS companies |
| 🏢 **Private Cloud (On-Premise)** | Resources built/maintained in a company's own data center | Hospitals, government (strict compliance) |
| 🌉 **Hybrid Cloud** | Combines on-premise + public cloud | Large enterprises (e.g., banks) migrating gradually |
| 🔀 **Multi-Cloud (Cross-Cloud)** | Uses multiple providers simultaneously (e.g., AWS + Azure) | Enterprises avoiding vendor lock-in |

---

## 🧭 Summary Table

| Concept | Purpose |
|---|---|
| IaaS / PaaS / SaaS | Increasing levels of management handed off to the provider |
| Public Cloud | Fully provider-hosted, "cloud-native" |
| Private Cloud | Fully self-hosted, for compliance-heavy organizations |
| Hybrid Cloud | Mix of on-premise + public cloud |
| Multi-Cloud | Multiple providers used together |
